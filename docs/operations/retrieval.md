# Memory retrieval

`pi_memory_search`, `pi_memory_read` and `pi_memory_list` use the same version and immutable generation as the summary injected at the start of a foreground run. Normal publication does not switch an existing run to a newer generation. Epoch changes, blocked pipelines, expired or retired support, invalid hashes and unsafe paths make the old view unavailable at the next tool boundary. A tool cannot select a version or generation.

v1 exposes `MEMORY.md`, `rollout_summaries/*.md` and `skills/<slug>/SKILL.md`. v2 exposes rollout summaries only. Explicit disallowed paths return `path_not_available_for_version`; there is no fallback. The injected compact summary, manifest, notes, raw memories, diffs, source snapshots and database are not reader targets.

Tools accept relative paths and absolute paths beneath the directory supplied by the injected read guidance. Absolute paths are converted to relative paths within the current validated generation before applying the same version allowlist. List/search treat an omitted or empty path as the generation root. Other directories, other versions/generations and `..` traversal remain unavailable. Results and citations use relative paths.

List returns immediate child files and directories, with a default/maximum limit of 2000. Search accepts one to eight trimmed queries with `match: any|all|all_on_same_line|all_within_lines`; normalized matching compares Unicode alphanumeric text. Search defaults to at most 200 results, and supports context lines and bounded multi-query windows. Matching is case sensitive unless `caseSensitive: false` is supplied. Results sort by relative path and line number. Search and list cursors bind the operation, query/filter, version and generation; a mismatched cursor returns `invalid_cursor` without content.

Results include relative paths, line numbers, known source IDs and readable evidence in `details`. Complete responses, including duplicated text/details, stay within 16 KiB. Search/list return a continuation cursor; reads return `nextStartLine`. Oversized individual lines are UTF-8-safe excerpts marked `truncated`; a line excerpt does not promise the complete original line. Large source lists expose at most 12 IDs per item with `sourceIdsTruncated` and `omittedSourceIds`; read the specific task or rollout for narrower provenance. Usage records the full validated support of the returned detail range rather than unrelated tasks or unreturned lines.

Reads accept 1-based `offset`/`startLine`, optional `maxLines`, and `maxTokens` (default 20000; zero uses that default). The host response ceiling still applies. Middle truncation preserves head/tail excerpts and reports retained ranges; omitted middle lines do not refresh usage.

Only successful detail reads increment usage, once per version, consumer session, foreground run and source. Summary injection, search hits and listing do not refresh retention. Errors omit file content and internal filesystem paths. Retrieval makes no model request.
