# Codex consolidation：内部 Agent 的上下文管理

证据固定于官方 `openai/codex@1cc7e2361237ce7244430ee1d581c77f95c57ac8`；本次只追踪 Agent 的计量、截断与压缩，不调查插件数据库，不调用模型。不需要用 main 的变化解释该基线。

## 已证明

- **MemoryConsolidation 没有专门禁用自动压缩。** Phase2 从父配置 `clone()`，改模型及若干功能，但保留 auto-compact 配置和 `TokenBudget` feature（[phase2.rs:294–353](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/phase2.rs#L294-L353)）。共享 `run_turn` 无条件执行 pre-sampling compaction（[turn.rs:179–188](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/turn.rs#L179-L188)）；工具/模型 step 后，超限且需要继续时执行 mid-turn compaction 并继续循环（[turn.rs:553–645](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/turn.rs#L553-L645)）。该路径没有按 internal source 排除。这里 MemoryConsolidation 的特殊分支是 Stop hook 拒绝即报错，不是关闭压缩（[turn.rs:656–665](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/turn.rs#L656-L665)）。

- **限制依据 token 状态，不是全部源文件 UTF-8 总字节。** 当前窗口计量使用最近服务器 `last_token_usage.total_tokens` 加之后新增 item 的估计；必要时另补旧 reasoning（[history.rs:902–925](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/context_manager/history.rs#L902-L925)）。完整历史估计另加 base instructions；item 按模型可见内容估计，不计 transport ID、metadata、外层 JSON escaping（[history.rs:623–650](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/context_manager/history.rs#L623-L650)、[1035–1042](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/context_manager/history.rs#L1035-L1042)）。文本启发式是 `ceil(UTF8_bytes / 4)`，**不是实际 tokenizer**（[truncate.rs:4,71–84](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/utils/string/src/truncate.rs#L4-L84)）。

- **自动压缩阈值与上下文硬限分开。** 默认 auto-compact threshold 是 resolved context window 的 90%，显式配置取更小值（[openai_models.rs:525–536](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/protocol/src/openai_models.rs#L525-L536)）。实际检查支持 Total / BodyAfterPrefix，并独立检查乘以 effective-percent 后的全窗口硬限；token-budget fallback 可加缓冲（[context_window.rs:58–120](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/context_window.rs#L58-L120)）。合并模型可能不同于父模型，不能直接套用父模型的 272k。

- **工具返回进入模型历史时会截断。** Session 传入模型的 truncation policy（[mod.rs:3647–3649](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/mod.rs#L3647-L3649)）；history 克隆输出再截断，保留完整 rollout payload。Function/Custom outputs 使用 per-output metadata override，或模型策略加 20% serialization allowance（[history.rs:495–554](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/context_manager/history.rs#L495-L554)、[output-truncation/lib.rs:14–54](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/utils/output-truncation/src/lib.rs#L14-L54)）。文本截掉中间，保留头尾；Token 模式也用字节启发式，不是精确分词（[truncate.rs:11–84](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/utils/string/src/truncate.rs#L11-L84)）。因此工具能够分批读源文件；不是所有文件全文永久留在窗口。

- **压缩实现有条件区别。** 未启用 TokenBudget 时，按 provider 能力走 remote V2 或 local summarization；启用时改成重置新窗口，**不生成摘要**（[turn.rs:1451–1508](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/turn.rs#L1451-L1508)、[compact_token_budget.rs:38–84](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/compact_token_budget.rs#L38-L84)）。Local 替换历史为保留用户输入与摘要，并重新估计 usage；其压缩请求本身超窗时还会删除最旧 item 重试（[compact.rs:311–320](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/compact.rs#L311-L320)、[356–393](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/compact.rs#L356-L393)）。

## 来源选择与本插件差异

- 上游从 DB 选择最多 `max_raw_memories_for_consolidation` 个 stage-one 输出，随后把它们写入工作区文件，不是直接把这些正文加入 prompt（[phase2.rs:94–110](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/phase2.rs#L94-L110)、[194–205](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/phase2.rs#L194-L205)）。模板只替换根目录和 diff 路径等变量；内部 Agent 启动普通 turn 后再用工具读文件（[prompts.rs:60–108](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/prompts.rs#L60-L108)、[runtime.rs:398–423](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/runtime.rs#L398-L423)）。本插件同样工具分页读取，不是将所有证据预装入首包。
- 上游 diff 来自 Git baseline，并在成功后重置 baseline（[workspace.rs:25–49](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/memories/write/src/workspace.rs#L25-L49)）；本插件 `src/pipeline/staging.ts:80–106` 对修改文件生成整文件删除/新增 hunks，因此增量更新时也可能放大读取量。首次创建文件时两者都可能包含全文，不能把该差异解释成首次构建必然更小。
- 本插件 `src/pipeline/consolidate.ts:160–162` 以整个序列化 context 的 UTF-8 字节数直接比较 token 数值导出的阈值；没有窗口压缩分支，超限直接返回 `blocked/context_budget`。分页读取限制单次响应，但不能阻止多次读取累积。该实现另设 12 次模型调用、40 次工具调用及 5 分钟总时限。

## 解释与边界

据此可解释“选择 256 sources”与有限窗口并不冲突：**候选集合大小 ≠ 单次请求载荷大小**；普通 Agent 的按需工具读取、输出截断、窗口压缩使累计处理量可大于一个窗口。这是代码机制支持的解释，**不是证明某次合并读完 256 份或实际触发过压缩**。

`186883 bytes` 按上游启发式约为 `46721 tokens`，但不同语言/内容会偏离，且指令、输出、工具 schemas 等仍占窗口，不能据此承诺安全余量。自动压缩也不是超大首包保险：pre-turn 检查发生在新输入录入之前，上游留有 TODO 明确指出尚未预估 pending input（[turn.rs:179–188](https://github.com/openai/codex/blob/1cc7e2361237ce7244430ee1d581c77f95c57ac8/codex-rs/core/src/session/turn.rs#L179-L188)）。因此不能把上游机制等同于“插件把所有证据塞进首包也必然安全”。
