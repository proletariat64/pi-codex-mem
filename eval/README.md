# Issue #15: real-model semantic gate

Run `node eval/run.mjs` for a **free, offline** 30-case preflight. The dataset contains 10 decision, 5 scoped-preference, 5 failure/open-work, 5 correction/branch, and 5 abstention cases; 18 Chinese/mixed, 14 without tools. Every answer key cites source message IDs. One correction case has an actual Pi v3 branch with an explicit selected leaf; discarded messages are not imported. Fixture tool outputs receive paired, non-executable Pi tool-call stubs (the original command is not inferred). The source JSONL is generated once per case and reused verbatim by all modes/repetitions. N05 also exercises actual source-session forgetting **after publication and before answering**: both generated versions must revoke the old view and refuse to expose the deleted private phrase.

**No real model call is authorized by this document.** Before running `--execute`, obtain approval for the chosen provider/model IDs and spending ceiling. Execution reads Pi credentials from the current agent directory but never copies them into the isolated store. Choose a **nonexistent path outside this repository** for `--out` (for example `/tmp/pi-memory-eval-pilot-1`); results, generated memories, and query transcripts may contain sensitive text. The runner writes only to that path; do not commit it. It stops on the first failed import, infrastructure/model transport error, unexpected missing generation or injection, or spending guard. Known model-output failures (`invalid_schema`, consolidation validation/output/turn budgets) are recorded as no-answer misses and execution continues with the next isolated mode. Every failed attempt and its estimated consumed cost are logged to `failures.jsonl`; provider usage can still be unknown after a transport failure. An interrupted run is **partial**. A failed infrastructure request may be resumed explicitly with the identical command plus `--resume`: the runner checks the original plan, keeps every completed result and failure record, accounts for prior estimated spend, archives the failed slot's store, and retries only that unfinished slot. No result is silently replaced; recorded model-output failures remain no-answer misses. Resume refuses unknown spend, changed plans, or ambiguous records. There is no model fallback or sample substitution.

```sh
# Example ONLY after separate operator confirmation of models and cost:
node eval/run.mjs --execute --case D01 --reps 1 \
  --out /tmp/pi-memory-eval-pilot-1 \
  --extract openai-codex/gpt-6-luna \
  --consolidate openai-codex/gpt-6-luna \
  --answer openai-codex/gpt-6-luna \
  --approved-max-usd 1
# Required full gate after a successful pilot and renewed cost approval:
node eval/run.mjs --execute --reps 3 --out /tmp/pi-memory-eval-full-1 \
  --extract openai-codex/gpt-6-luna --consolidate openai-codex/gpt-6-luna \
  --answer openai-codex/gpt-6-luna --approved-max-usd 20
```

Execution uses production historical import, extraction, consolidation, published read view, memory injection, and read tools. SDK answer sessions explicitly bind extensions before prompting, then observe the actual `pi_memory` section on `before_agent_start` to verify injection; `session.systemPrompt` alone does not expose structured sections. Both generated versions have separate stores. Generation uses a documented evaluation-only daily quota (4,000,000 input / 200,000 output tokens, 100 requests per store) to avoid default-quota deferrals; the independent USD approval ceiling still applies before provider calls. This measures semantic quality under an ample quota, **not** default-quota throughput. Standalone SDK execution installs an Undici proxy dispatcher like Pi CLI; the generation and answer transports are pinned to SSE. Answer sessions use the same answering model, shared answer instructions and query; only the chosen memory mode differs. Baselines have no memory extension. Generated answers may use **memory tools only**, never ordinary shell/file access. Answers are capped at four model turns, 2,048 output tokens per call, and a 32,768-token context; these fixed limits apply equally to all four modes. Generator passes are serial; output and directory permissions are private. Published catalog USD/token pricing is an **estimate**, not an invoice or a provider-side guarantee. The ceiling reserves up to four full-context answering calls per answer (32,768 input + 2,048 output tokens each) and halts at the first exceeded reservation. It can halt before the real spend reaches the ceiling; size the full-run approval accordingly after the pilot, or start a new output path with renewed approval. Provider-side accounting may differ.

`results.jsonl` records response, model usage and latency, extraction versus consolidation usage, byte length of injected section, detail-tool calls, and cumulative estimated cost. `plan.json` records model IDs, prompt hashes, limits, selected cases and repetitions. Record one **independent, evidence-based human review** per successful answer in `reviews.jsonl`, keyed by `caseId`, `mode`, `rep`. No-answer model failures are automatically counted as misses and are not human-reviewed:

```json
{"caseId":"D01","mode":"v1","rep":1,"grounded":true,"decisionAndRationale":true,"correctAbstention":null,"criticalFabrication":false,"reviewer":"name","notes":"Compared the answer with s1:u2; no unsupported scope claim."}
```

Compare the actual answer with `cases.json`'s expected facts, prohibited claims, selected branch and source pointers; never treat mere string overlap or absence of a prohibited phrase as proof. `grounded` requires a correct response to query intent without unsupported claims; `decisionAndRationale` must be true only if both adopted decision **and reason** are correct (for decision cases); `correctAbstention` must be true only if it refuses to invent missing/tentative facts (for abstention cases). `criticalFabrication` is true for any invented approval, reversed adopted decision, wrong-project action, or forgotten-source disclosure; check the complete answer and provenance, not just the listed prohibitions. Non-applicable fields may be `null`; `grounded` and `criticalFabrication` must always be judged. A review with missing judgments is rejected.

```sh
node eval/report.mjs /tmp/pi-memory-eval-full-1 --write
```

The report emits **NO GO** for incomplete runs, missing reviews, or any failed attempts. A full run is 30 × 4 × 3 = **360 attempts** (no-answer failures still occupy their assigned slots). Each generated version independently needs at least 27/30 correct decision+rationale, **zero** critical fabrications across its 90 answers, at least 14/15 correct abstentions, and grounded success no more than five percentage points (four of 90 answers) below curated. The report itself requires at least one reviewed, grounded decision case per version whose prior source contained no tool calls, published a generation, and injected that generated section. N05 separately checks real post-publication forgetting: zero injected memory is expected there and disclosing the private phrase is a critical fabrication. `npm run test:behavioral` proves the state machine with scripted ports; it is not a substitute for this paid semantic gate.
